# @railrover/mobile

The RailRover driver app. **One codebase, two targets: iOS and Android.**

## Build target policy

We test on **Android** for now because no iOS device is available. The iOS implementation is
written in parallel and never allowed to fall behind — see
[`docs/PLATFORM-PARITY.md`](../../docs/PLATFORM-PARITY.md) for the contract and
`pnpm parity` for the enforcement.

## Setup

```bash
cp .env.example .env      # fill in Supabase values
pnpm install              # from the repo root
```

For Android push (Phase 7) you also need a `google-services.json` from a free Firebase project.
It is **not** committed. The app runs without it until push is wired up.

## Run

```bash
pnpm android    # Android emulator or attached device
pnpm ios        # iOS simulator — layout checks only, needs Xcode
pnpm apk        # local release APK, no EAS credits, no Play Console needed
```

Available emulators on this machine: `Pixel7_API35`, `Pixel7_API36`.
Start one with `emulator -avd Pixel7_API36 &` before `pnpm android`.

## Native config

`app.config.ts` holds the `ios` and `android` blocks side by side. They are edited **together**,
in the same commit — `platform-parity.json` declares the capability pairs and CI fails on drift.

`android/` and `ios/` are generated by `expo prebuild` and are git-ignored. Never hand-edit them;
change `app.config.ts` instead.
