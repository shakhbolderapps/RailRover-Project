# AGENTS.md — RailRover

Read this file first, every session. It is the operating contract for this repo.

**Source of truth:** `docs/RailRover-SOW-TechStack-Timeline.pdf` (Doc Ref QNZJP-QGWUO-ST8BC-3XA3G).
A searchable text extract lives at `docs/RailRover-SOW.txt`. Per-feature specs copied verbatim
from that SOW live in `specs/`. **The SOW wins every disagreement.** If code and spec conflict,
the spec is right until the human says otherwise.

`docs/RailRover-Agentic-Roadmap.md` is the execution plan (phases, stack swaps, risk register).
It is advisory, not contractual.

## 1. What this product is

A crowd-sourced railroad-crossing status app. Drivers report a crossing **blocked** or **clear**
in two taps; the app checks fresh blocked reports against the driver's **active route** in real
time and reroutes around the blockage *before* they reach it. Destination search ranks route
options by how many crossings each one crosses. MVP is a pilot around Toledo, Ohio.

## 2. Build target: Android now, iOS in lockstep

**Client directive (binding):** test on Android (APK) for now — no iOS device is available. But
**the iOS implementation must never fall behind.** Every feature, screen, and change ships for
both platforms in the same commit, so an iOS build can be produced the day a device appears,
with zero catch-up work.

This is enforced, not trusted. See `docs/PLATFORM-PARITY.md` for the full contract. The short
version, and these are hard rules:

1. **One codebase.** React Native + Expo, managed workflow. No `android/` or `ios/` directories
   in git — they are generated by `expo prebuild`. Native config lives in `app.config.ts`, where
   the `ios` and `android` blocks are maintained **side by side, in the same edit**.
2. **No orphan platform forks.** A `Foo.android.tsx` without a sibling `Foo.ios.tsx` fails CI.
3. **No one-armed `Platform.select`.** Every `Platform.select({...})` must have both `ios` and
   `android` keys (or a `default`). `Platform.OS === 'android'` branches must have an else path
   that is correct on iOS, not a no-op.
4. **Every new permission, capability, or native module gets its iOS declaration in the same
   commit** — purpose string, `infoPlist` entry, privacy-manifest reason code, entitlement.
   An Android permission added alone fails review.
5. **CI typechecks and prebuilds both platforms** on every PR. iOS *compiles* in CI even though
   we cannot *run* it.
6. **Known iOS gaps are registered, never silent.** If something genuinely cannot work on iOS
   yet (APNs needs a paid Apple account), it goes in the gap register in
   `docs/PLATFORM-PARITY.md` with its unblock condition. "I'll do iOS later" is not a gap, it is
   a bug.

Run `pnpm parity` before every commit. CI runs it too.

## 3. Stack

| Layer | Choice | Notes |
|---|---|---|
| Mobile | Expo (managed) + expo-router + TypeScript strict | iOS + Android from one source |
| Map | MapLibre (`@maplibre/maplibre-react-native`) + OpenFreeMap tiles | keyless; attribution required |
| Admin | Vite + React + TS + `maplibre-gl` | |
| Backend | Supabase (Postgres + PostGIS, Auth, Realtime, Edge Functions) | |
| Routing | OpenRouteService via **adapter** (`packages/shared/src/routing`) | never call ORS directly from app code |
| Geocoding | Photon (typeahead) + Nominatim (resolve) | Nominatim: <=1 req/s, real User-Agent |
| Push | Expo Push + FCM | Android works now; iOS blocked on Apple account |
| Crossing data | FRA Crossing Inventory Form 71, dataset `m2f8-22s6` | at-grade + active + public only |

Deviations from the SOW's stack (Google Maps -> MapLibre/ORS) exist because the zero-cost
constraint forbids a billing-enabled GCP account. See `decisions/0001`.

## 4. Rules that are easy to get wrong — do not re-litigate these

Each has an ADR in `decisions/`. Read it before arguing with it.

- **200 feet is the route CORRIDOR WIDTH, not an alert distance.** It decides whether a crossing
  counts as *on* the route. A fresh blocked crossing is flagged **however far ahead it is** —
  there is no proximity threshold on the alert. Stored as `route_corridor_meters` (~61 m).
  ADR `0003`.
- **Crossing status is computed at read time, never stored.** `red|yellow|green|unknown` is a
  pure function of `(latest report status, latest report timestamp, now, freshness_window)`.
  Never add a `color` column. Never write a cron job to flip red->yellow. ADR `0002`.
- **Green comes only from an explicit clear report.** A crossing never returns to green on a
  timer. A blocked report aging past the freshness window goes **yellow** (blocked but
  unconfirmed), never green.
- **`unknown` is a fourth state, distinct from green.** A crossing with no reports is
  unconfirmed, not clear. Never collapse `unknown` into `green`. ADR `0002`.
- **Distance and rate-limit checks are server-side.** Report submission goes through the
  `submit_report` RPC. A client-side radius check is decoration. ADR `0004`.
- **Freshness window (15 min), corridor (200 ft), report radius (~1 mi) are configurable.** They
  live in the `app_config` table, not in source constants, because the SOW says they ship at
  these defaults and are tuned during the pilot.
- **Reroute is route-avoidance, not turn-by-turn navigation.** Build an avoidance polygon around
  the blocked crossing and re-request. MVP avoids **one** crossing, not several. ADR `0005`.
- **Grade-separated crossings are excluded at ingest.** An overpass can never be blocked by a
  train. Assert zero grade-separated rows in tests.
- **No note field on reports.** The SOW is explicit: two taps, under five seconds, while driving.

## 5. Layout

```
apps/mobile        Expo app (iOS + Android, one source)
apps/admin         Vite + React web admin panel
packages/shared    types, crossing-status logic, geo helpers, routing adapter — platform-free
supabase/          migrations, RPCs, Edge Functions, seed, pgTAP tests
specs/             one file per SOW feature, acceptance criteria VERBATIM
decisions/         ADR log — one file per non-obvious choice
scripts/           FRA ingest, parity check, spec generation, APK build, doctor
docs/              SOW, roadmap, platform-parity contract
```

`packages/shared` must stay free of React Native and DOM imports — both apps and the test suite
depend on it. Status logic and geo math live there so they are tested once and correct on both
platforms.

## 6. Definition of Done — enforced every task

A task is not done until all six are true:

1. Code implemented for **both platforms** (`pnpm parity` passes).
2. Unit tests written, passing.
3. **Every acceptance criterion in the relevant `specs/` file is mapped to a named assertion.**
   Reference the criterion number in the test name.
4. One manual pass on the Android emulator (or device) — and the iOS path reviewed for
   correctness even though it cannot be run.
5. Spec file updated **only if reality diverged from the SOW**, with a note saying why. Never
   quietly edit acceptance criteria to match the implementation.
6. `pnpm verify` green.

## 7. The solo-QA rule

One human is developer and QA. That is countered structurally, not by discipline:

- **Write the assertion from the SOW acceptance criterion BEFORE the implementation exists.**
- **Never let one agent session write both the implementation and the assertion for the same
  criterion.** Separate sessions, separate prompts.
- Agents must not modify files in `specs/` unless the task is explicitly "update the spec".

## 8. Task sizing

One session = one feature from SOW §6, or one slice of a big one.

- Too big: "Build Module 4."
- Right: "Implement `crossings_on_route()` RPC with corridor and ahead-of-driver filtering, plus
  pgTAP tests against the seeded Toledo fixture."

## 9. Commands

```bash
pnpm install            # bootstrap
pnpm verify             # parity + typecheck + lint + test — run before every commit
pnpm parity             # platform-parity check only
pnpm android            # run on Android emulator/device
pnpm ios                # run on iOS simulator (config must always be valid)
pnpm apk                # build a local release APK (no EAS credits needed)
pnpm admin              # run the web admin panel
pnpm routing:up         # local Valhalla/OSRM container (requires Docker — see §10)
pnpm ingest:dry         # preview the FRA crossing ingest, no credentials needed
pnpm ingest -- --radius 50   # load crossings (needs SUPABASE_SERVICE_ROLE_KEY)
pnpm db:push            # apply migrations
pnpm db:test            # run the pgTAP suite
```

## 10. Environment gaps on this machine — do not silently work around these

- **Docker is not installed.** So `supabase start` (local DB) and the local routing container are
  unavailable. Dev uses the **hosted Supabase free project**; migrations still live in
  `supabase/migrations` so the local path is a drop-in later. Automated routing tests use the
  **fixture-backed adapter**, never live ORS. ADR `0007`.
- **No Apple Developer Program account.** No iOS device builds, TestFlight, or APNs. iOS code is
  still written and typechecked in full. `docs/PLATFORM-PARITY.md` tracks it.
- **No physical Android device.** Pixel 7 AVDs (API 35, 36) are available.

## 11. Never do

- Never store a computed crossing colour in the database.
- Never treat 200 ft as a distance-to-alert threshold.
- Never let a crossing turn green without a clear report.
- Never call ORS, Photon, or Nominatim from app code — go through the adapters in
  `packages/shared`.
- Never add an Android permission without its iOS counterpart in the same commit.
- Never commit `apps/mobile/android/` or `apps/mobile/ios/`.
- Never paraphrase a SOW acceptance criterion.
- Never hardcode the freshness window, corridor width, or report radius.
- Never add a note/comment field to the report flow.
- Never commit an API key, service-role key, or `.env`.
